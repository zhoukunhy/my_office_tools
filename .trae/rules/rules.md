# 办公工具箱 Vibe‑Coding 项目规则

## 🎯项目核心红线【最高优先级，严禁违反】
1. **全部文件处理必须浏览器本地完成，禁止上传任何用户文件到后端/远程服务器**。禁止编写文件上传接口、fetch上传文件、axios文件提交；所有PDF、图片、文本运算全部前端内存/WebWorker执行。
2. 无后端服务，本项目是纯静态前端项目，**不要创建server、api后端目录**。
3. 无广告、无埋点、无用户统计上报；localStorage仅本地保存用户输入，绝不向外发送。
4. 新增第三方库必须先询问用户，禁止私自引入重型依赖；优先使用成熟前端本地库：pdfjs‑dist、browser‑image‑compressor、qrcode。
5. 功能严格对齐PRD文档（canvas:office‑tool‑web‑prd），没有需求不要额外自发增加功能。

## 🧱架构&目录约束
1. 技术栈固定：Vue3 Composition‑API + Vite5 + TypeScript + TailwindCSS；不引入Sass/Less，不换框架。
2. 目录约定：
- `src/views/tools/`：每个工具独立页面组件，一个工具一个vue文件
- `src/components/common/`：全局通用UI组件（上传区、进度条、复制按钮、弹窗）
- `src/composables/`：可复用逻辑（localStorage缓存、文件处理、异常捕获）
- `src/config/tools.ts`：**统一维护全部工具元数据**（名称、分类、简介、路由），禁止分散硬编码工具列表。
- `src/router/index.ts`：路由全部在此注册，新增工具路由必须在这里添加。
3. UI风格统一：所有工具页面复用同一套交互模板：拖拽上传区域 → 参数配置 → 预览面板 → 进度状态 → 结果输出 → 下载/复制按钮。保证视觉、交互一致性。
4. 修改代码遵循最小改动原则；不要大范围重构无关代码；只修改当前任务相关文件。

## 📝TypeScript & 编码规范
1. 开启strict模式，**禁止滥用any**；优先unknown做类型收窄。
2. 变量、函数 camelCase；Vue组件 PascalCase；常量 UPPER_SNAKE_CASE。
3. 禁止空catch；所有解析、文件处理逻辑必须 try‑catch，给出友好中文错误提示，不能页面崩溃白屏。
4. 耗时文件处理逻辑（大图片、大PDF）放到 WebWorker，**禁止阻塞主线程**；增加loading/进度状态。
5. 事件防抖：resize、输入搜索使用防抖200ms。
6. 组件不要写过大单文件；单vue文件尽量控制在350行以内，复杂逻辑抽 composable。
7. localStorage缓存策略：工具输入内容自动本地缓存；组件onMount读取缓存；提供全局清除缓存按钮；避免缓存无限膨胀。

## 📱UI / 响应式约束
1. 必须做好移动端适配：小屏侧边栏转为抽屉弹出模式。
2. 主题：浅色/暗黑模式切换，全局生效。
3. 全局支持工具模糊搜索，基于`tools.ts`配置检索。
4. 页面底部必须展示隐私声明：所有文件仅在浏览器本地处理，不上传服务器。

## 🚀开发迭代工作规则（Vibe Coding契约）
1. 开发遵循：**骨架搭建 → 分批实现工具功能 → bug修复 → 体验打磨 → 部署准备**；禁止一次性写完全部工具。
2. 每完成一批功能，输出变更清单：改动文件列表，告知如何手动验证效果。
3. bug修复：复现问题，给出修复代码，描述验证步骤。
4. 完成功能后，不要编造后端服务，输出静态部署说明（Vercel/Nginx）。
5. 如果需求模糊，先简短提问确认，不直接脑补实现。

## ❌禁止清单
- 禁止生成后端接口、express/nest服务代码
- 禁止把用户文件发送到任意外部接口
- 禁止自发增加PRD以外功能（登录、会员、分享、埋点统计）
- 禁止UI风格跳变，每个工具页面交互模板不一致
- 禁止忽略异常捕获，允许页面崩溃
